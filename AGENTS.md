# AGENTS.md: guide for AI assistants

This repository was written by an AI coding agent (Claude Code), working from one user's requirements. This file is for AI assistants (Claude Code, Codex, Cursor, Copilot, ...) that are asked to **deploy shuoshuo on a user's machine** or to **adapt the approach** to a different setup. Read the whole file before acting. User-facing docs: README.md (Chinese) and README.en.md (English).

## What it is

Push-to-talk voice input for Windows and macOS. The user holds a hotkey (default CapsLock on Windows, Right Option on macOS) and speaks. On release, the transcript is typed at the cursor of whatever app has focus. Recognition runs on the user's own NVIDIA GPU server (Qwen3-ASR-1.7B). Clients are thin and reach the server over LAN or Tailscale. No cloud services.

## Core design decisions (keep these when adapting)

1. **Whole-utterance upload, not streaming.** Record locally until key release, then POST the complete WAV once, and the server transcribes the full clip. A bad network only adds latency; it never degrades accuracy. The client retries 3 times, and on final failure keeps the audio for a manual "retry last" from the tray. Speech is never silently dropped.
2. **Thin client, fat server.** The client does hotkey, mic, HTTP, text injection and tray, with no ML dependencies. The server holds the model and the hotwords. One server serves many devices.
3. **Hotwords as context biasing.** Non-comment lines of `server/hotwords.txt` are joined with newlines and passed as Qwen3-ASR's `context` (it goes into the system prompt). This fixes proper nouns and English terms in Chinese speech. Measured: "Postgre SQL" → "PostgreSQL". In our tests it did not hallucinate hotwords on silence or noise. The file is reloaded on mtime change, so no restart is needed.
4. **Never type into the wrong window.** The client records the foreground window at key release. If it changed by the time the result arrives (slow network, manual retry), the text goes to the clipboard plus a notification instead of being typed.
5. **Digits via rule-based ITN.** Qwen3-ASR writes every number as Chinese characters (一百二十次, 二零二六年). `server/itn.py` converts them to digits after recognition. It is conservative on purpose: when in doubt it leaves the text alone. Idioms, function words, approximations (三五天), ordinals (第三章) and small counts with classifiers (三个方法) stay as characters. `--no-itn` disables it.
6. **Auth.** A shared bearer token in `server/.token`, auto-generated by `run_server.sh`. `run_server.sh` binds `0.0.0.0:8765`.

## Deployment playbook

**Ask the user first; don't guess:**
- Which machine has the NVIDIA GPU? Linux, or WSL2 on Windows? Free VRAM: about 5 GB for 1.7B, about 2.5 GB (estimate) for 0.6B.
- Where should model weights live? This is about 4.7 GB.
- Which Windows devices will use it? Same LAN, or remote (suggest Tailscale)?
- Hotkey preference? The default is CapsLock; a short tap still toggles CapsLock.

Tell the user about large downloads before starting: torch with CUDA libraries is about 3 GB, and the model is 4.7 GB.

### 1. Server (Linux or WSL2, NVIDIA GPU)

```bash
cd server && ./setup.sh
# optional: put the model somewhere specific
hf download Qwen/Qwen3-ASR-1.7B --local-dir /path/to/models/Qwen3-ASR-1.7B
echo 'SHUOSHUO_MODEL=/path/to/models/Qwen3-ASR-1.7B' > .env
./run_server.sh          # first start: model load ~2 s on a 5090 (plus download time if no local copy)
```

Verify:

```bash
curl -s localhost:8765/health                                   # {"ok": true}
ffmpeg -i any.m4a -ac 1 -ar 16000 -sample_fmt s16 test.wav      # /asr only accepts 16-bit mono WAV
curl -s -H "Authorization: Bearer $(cat .token)" -H "Content-Type: audio/wav" \
     --data-binary @test.wav localhost:8765/asr                 # {"text": "...", ...}
```

No recording at hand? On Windows, `System.Speech` (PowerShell) can synthesize a test WAV. A Chinese voice (Huihui) reading a sentence with English terms is a good hotword test.

### 2. Windows client

```bat
py -m venv %LOCALAPPDATA%\shuoshuo\venv
%LOCALAPPDATA%\shuoshuo\venv\Scripts\pip install -r client\requirements.txt
copy client\config.example.ini client\config.ini
```

Fill in `server` and `token` in `config.ini`, then run `client\start.bat`. If the server runs in WSL on the same PC, set `server_cmd = wsl.exe -d <distro> -- /abs/path/server/run_server.sh`. The client then starts it hidden when `/health` fails, and terminates it on exit. Killing `wsl.exe` also kills the Linux process, which frees the VRAM.

Verify: `client/shuoshuo.log` shows lines like `4.2s 音频 → 20 字，往返 300 ms（推理 280 ms）`. The live test (hold the hotkey, speak) must be done by the **user**; see the safety rules.

### 2b. macOS client

```bash
python3 -m venv ~/Library/Application\ Support/shuoshuo/venv
~/Library/Application\ Support/shuoshuo/venv/bin/pip install -r client/requirements.txt
cp client/config.example.ini client/config.ini   # or: client/build_mac.sh → dist/shuoshuo.app
```

The user must grant Accessibility, Input Monitoring and Microphone in System Settings → Privacy & Security. Grants attach to the launching binary: the terminal app for `start.sh` (often an IDE like Cursor, which is a broad grant; prefer the `.app`), or `shuoshuo.app`. The hotkey thread retries every 3 s, so granting takes effect without restart.

### 3. Other devices

Use the portable build (`client\build.ps1` → copy `client\dist\shuoshuo\`, edit its `config.ini`). For remote access, put the server and the devices on the same Tailscale tailnet. Have the user open `http://<server-node>:8765/health` in a browser on the device.

## Pitfalls we hit (save yourself the time)

**Server**
- `qwen-asr` imports `nagisa` (forced-aligner only) at import time, and that initializes DyNet (~512 MB RAM). `server.py` stubs it via `sys.modules`. Install `qwen-asr` with `--no-deps`: its declared deps pull gradio, flask and vllm, none of which are needed here.
- `qwen-asr` pins `transformers==4.57.6`, so use a dedicated venv. `uv venv` may silently pick a conda env's Python as the venv base, which then breaks if that conda env changes. `setup.sh` uses `--managed-python` for that reason.
- RTX 50xx (Blackwell) needs CUDA 12.8 torch builds (`cu128`).
- HF `hf_xet` downloads can hang at the very end: sockets sit in CLOSE-WAIT, and the file is preallocated with holes, so it has the right size but the wrong hash. Always verify sha256 against `https://huggingface.co/api/models/<repo>?blobs=true`. The ModelScope mirror (`https://modelscope.cn/models/<org>/<name>/resolve/master/<file>`) supports Range requests; parallel chunked download from it was faster.
- `transformers` logs a `pad_token_id` warning on every `generate`; `server.py` lowers the verbosity.
- `qwen-asr` only zero-pads short chunks when it splits long audio. A short single clip goes straight into the Whisper STFT, so empty or < ~12.5 ms audio raises → 500. That is what a client whose mic delivers no data sends. `server.py` rejects < 0.1 s with 400, and the client doesn't upload such recordings; it notifies instead.
- Numbers: Qwen3-ASR outputs spoken-form Chinese numerals, and putting digit examples or instructions in `context` does **not** change that. Off-the-shelf ITN libraries were tried and rejected:
  - `cn2an.transform` over-converts: 一起 → 1起, 四川 → 4川.
  - WeTextProcessing / `wetext` without `enable_0_to_9` produce writing styles unsuited to Chinese prose: 三月五号 → 03/05, 下午三点半 → 3:30p.m., 十分钟 → 10min. They also mis-convert 十分重要 → 10分重要 and 几十个 → 几10个.
  - Turning `enable_0_to_9` on makes it worse (一模一样 → 1模1样), and `wetext` with that option returns empty strings.

  Hence the custom rules in `itn.py`. Two-character digit runs (五一, 四六级, 五四运动) are kept unless they contain 零 or are followed by 后/年. Fixed expressions such as 二百五 and 三七二十一 live in an exception list.
- Inference latency grows with output length: about 60–70 ms per second of speech with the transformers backend. vLLM would be faster but needs torch 2.9.1, so it needs a separate env (not implemented).

**Networking (WSL2)**
- In mirrored networking mode, Windows and WSL share one port space. Check for conflicts on the Windows side (for example, IDEs hold local ports).
- WSL's Hyper-V firewall blocks inbound by default. Windows → WSL works via `127.0.0.1`.
- If WSL runs its own `tailscaled`, it is a separate tailnet node; remote devices should target that node. Testing that node's IP from the **same** Windows host gives a **false timeout**: the Windows node's IP is mirrored into WSL as a local address, so replies are routed to `lo`. Verify from a real second device.

**Windows client (ctypes)**
- The low-level keyboard hook needs a message loop on the thread that installed it.
- Keep a reference to the `WINFUNCTYPE` callback, or a later callback crashes.
- Set `argtypes` and `restype` on Win32 functions; `LPARAM` and handles are 64-bit.
- The `INPUT` union must include `MOUSEINPUT`, or `sizeof(INPUT)` is not 40 and `SendInput` fails.
- Mark your own injected keys via `dwExtraInfo`. Don't filter on `LLKHF_INJECTED`: that would break hotkeys produced by AutoHotkey or mouse-software remaps.
- `SendInput` with `KEYEVENTF_UNICODE` (UTF-16 code units, so emoji are surrogate pairs) bypasses the IME and doesn't touch the clipboard.
- `OpenClipboard(NULL)` makes `SetClipboardData` fail; open it with a hidden window instead.
- `pythonw` has no stdout or stderr: log to a file and install `threading.excepthook`.
- Build the `urllib` opener with `ProxyHandler({})`. System proxies (Clash and the like) otherwise hijack LAN and Tailscale requests.
- UIPI: you cannot hook or type into elevated windows unless the client is elevated too.
- PortAudio MME captures 16 kHz directly. Fallback is the device default rate, and the server resamples. Open the stream per key press so a changed default mic is picked up.

**macOS client (pyobjc)**
- CapsLock hold isn't reliably detectable (toggle semantics + debounce). Default is Right Option; modifiers arrive as `kCGEventFlagsChanged`, and down/up comes from the device-specific flag bit (`0x40` for right Option), not the keycode.
- A lone modifier tap does nothing, so `replay_tap` only re-posts F-keys.
- The tap gets disabled by `kCGEventTapDisabledByTimeout` / `...ByUserInput`; re-enable it in the callback or the hotkey silently dies.
- Mark injected events with `kCGEventSourceUserData`, the equivalent of `dwExtraInfo`.
- `CGEventKeyboardSetUnicodeString` takes at most ~20 UTF-16 units per event; don't split surrogate pairs. With Pinyin and similar IMEs active, these events may be routed through the IME, so `mac_inject = auto` pastes via clipboard + ⌘V instead and restores the previous clipboard (unless it changed meanwhile).
- Carbon TIS (`TISCopyCurrentKeyboardInputSource`) must run on the main thread; `platform_mac._on_main` dispatches it.
- pystray's darwin backend updates NSStatusItem on whatever thread calls it; route `icon.icon/title/update_menu/visible` through `plat.ui`.
- "Same window" check: frontmost app pid + its frontmost layer-0 window number from `CGWindowListCopyWindowInfo`.
- PyInstaller `--add-data` paths resolve relative to `--specpath`; use absolute paths. Re-signing ad-hoc on every build can invalidate TCC grants: remove and re-add the app in Privacy settings.

**Windows tooling**
- PowerShell 5.1 parses BOM-less `.ps1` files as the ANSI code page (GBK on Chinese Windows). Save scripts that contain non-ASCII as UTF-8 **with BOM**. Its output, seen from WSL, is GBK too (`iconv -f GBK -t UTF-8`).
- In zsh, `pkill -f <pattern>` can match your own shell command. Use the `[x]yz` regex trick.

## Safety rules for agents

- Never commit `server/.token`, `server/.env`, `server/hotwords.txt` or `client/config.ini`. They are git-ignored on purpose.
- Don't expose the server beyond localhost without a token. Don't change firewall, router or Tailscale settings without asking.
- Don't inject keystrokes into the user's desktop during automated tests. To test typing, create your own window, verify `GetForegroundWindow()` equals it **before** injecting, wait until the text stops changing, then close it. Abort if focus can't be acquired.
- Tests that set the clipboard overwrite the user's clipboard; say so.
- Don't record from the user's microphone in automated tests. Feed synthetic audio, for example TTS, through the recognizer instead.

## Adapting to other setups

- **Smaller GPU:** set `SHUOSHUO_MODEL` to `Qwen/Qwen3-ASR-0.6B`.
- **No GPU:** this server is not meant for CPU. Keep the same `/asr` contract and swap the backend, for example sherpa-onnx with SenseVoice-Small, which is fast on CPU.
- **iOS (not implemented):** there are no global hotkeys, and custom keyboards cannot use the microphone. Options:
  - a Shortcuts flow (Record Audio → Get Contents of URL with the token header → Copy to Clipboard). The server would need to accept m4a;
  - an OpenAI-compatible `POST /v1/audio/transcriptions` endpoint, so that third-party keyboards with a self-hosted mode can call it.
- **Linux client (not implemented):** use evdev for the hotkey. For injection, use xdotool on X11, or ydotool/wtype on Wayland.

## Conventions when editing code

Chinese comments and UI strings, English identifiers. Keep the client stdlib-first with no heavy dependencies: shared logic in `shuoshuo.py`, OS specifics behind the same small interface in `platform_win.py` / `platform_mac.py` (`HOTKEYS`, `DEFAULT_HOTKEY`, `KeyHook`, `type_text`, `replay_tap`, `set_clipboard`, `foreground`, `play`, `open_file`, `spawn`, `single_instance`, `alert`, `notify`, `ui`, `data_dir`, `setup_app`). Keep the server's HTTP contract stable, because deployed clients depend on it. After client changes, re-run `client\build.ps1` / `client/build_mac.sh` for the portable builds.
